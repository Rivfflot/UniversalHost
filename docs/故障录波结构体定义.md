# 故障录波结构体定义

## 基本约定

- 数据存储数组使用**环形缓冲区**。
- **当前支持的平台均采用小端序，上位机暂时只支持小端录波数据。**包括 C28x（28335、28377、28377D）和 ARM（ZYNQ、STM32）；以后使用大端平台时再扩展上位机支持。
- 本文所有字节均指 **8 位字节**。字节偏移从 `0` 开始，范围包含两端。
- `header` 的偏移相对于整个录波数据起点；`channel_info` 的偏移相对于每个通道信息条目的起点。
- 数据按通道分别存放，每个通道包含 `record_length` 个采样点。
- `bool` 固定占 1 字节，`float` / `double` 分别采用 IEEE 754 binary32 / binary64。平台原生类型与这些定义不一致时，必须由下位机适配。
- C28x 录波通道禁止使用 `uint8`、`int8` 和 `bool`，即禁止类型编码 `0`、`1`、`2`。

## 整体布局

| 顺序 | 段 | 数量 / 长度 | 内容 |
| --- | --- | --- | --- |
| 1 | `header` | 50 字节 | 标识、通道数量、采样率、录波点数、环形缓冲区索引、保留字段 |
| 2 | `channel_info[channel_num]` | `38 * channel_num` 字节 | 每个通道 38 字节，包含名称、类型和保留字段 |
| 3 | `data` | 按各通道类型和点数确定 | `sample_data1`、`sample_data2`、……依次存放 |

数据区起始偏移为：

```text
data_offset = 50 + 38 * channel_num
```

字段之间和各段之间均无额外填充。下位机结构体使用 `#pragma pack(1)`；直接上传结构体内存时，其实际字段大小和偏移必须与本文一致。

## header：50 字节

| 字节偏移 | 字节数 | 名称 | 数据类型 | 说明 |
| --- | --- | --- | --- | --- |
| `0 .. 3` | 4 | `magic` | `uint32` | 固定标识 `0x52454344`（`"RECD"`） |
| `4 .. 5` | 2 | `channel_num` | `uint16` | 通道数量 |
| `6 .. 9` | 4 | `sample_rate` | `uint32` | 采样率，单位 Hz |
| `10 .. 13` | 4 | `record_length` | `uint32` | 每个通道的缓冲区容量，即录波点数；不是字节数 |
| `14 .. 17` | 4 | `current_index` | `uint32` | 下一个采样点的写入索引，也是按时间顺序读取的起点；前一个位置是最新写入值 |
| `18 .. 49` | 32 | `rsvd` | `uint16[16]` | 保留 |

长度核对：`4 + 2 + 4 + 4 + 4 + 2 * 16 = 50` 字节。

`magic` 按小端序读取为数值 `0x52454344`，存储字节为 `44 43 45 52`；`"RECD"` 是该数值的标识名称。

## channel_info：每个通道 38 字节

条目数量为 `channel_num`，合计 `38 * channel_num` 字节。

| 条目内字节偏移 | 字节数 | 名称 | 数据类型 | 说明 |
| --- | --- | --- | --- | --- |
| `0 .. 19` | 20 | `name` | `char[20]` | ASCII 名称，C 字符串，以 `\0` 结尾 |
| `20 .. 21` | 2 | `type` | `uint16` | 类型，见下表 |
| `22 .. 37` | 16 | `rsvd` | `uint16[8]` | 保留 |

长度核对：`20 + 2 + 2 * 8 = 38` 字节。

### name 名称格式

- 固定占 20 个 8 位字节，采用 ASCII 编码。
- 名称最多包含 19 个 ASCII 字符，第 20 个字节必须能容纳字符串终止符 `\0`。
- 读取时以第一个 `\0` 为名称结束位置，终止符后的字节不属于名称。
- 下位机通过 `CHANNEL_LIST` 的通道标识符生成名称，并在编译时检查名称长度（计入终止符）不超过 20。

### type 类型编码

| 编码（十进制） | 数据类型 | 每个采样值的字节数 | 表示方式 |
| --- | --- | --- | --- |
| `0` | `bool` | 1 | `0x00` 为 false，`0x01` 为 true |
| `1` | `s8` | 1 | 8 位有符号整数 |
| `2` | `u8` | 1 | 8 位无符号整数 |
| `3` | `s16` | 2 | 16 位有符号整数 |
| `4` | `u16` | 2 | 16 位无符号整数 |
| `5` | `s32` | 4 | 32 位有符号整数 |
| `6` | `u32` | 4 | 32 位无符号整数 |
| `7` | `float` | 4 | IEEE 754 binary32 |
| `8` | `s64` | 8 | 64 位有符号整数 |
| `9` | `u64` | 8 | 64 位无符号整数 |
| `10` | `double` | 8 | IEEE 754 binary64 |

`bool` 的逻辑类型对应 `<stdbool.h>` 提供的 `bool`，录波中的存储宽度固定为 1 个 8 位字节。所有多字节整数和浮点值均按小端序存放。类型编码 `0`、`1`、`2` 适用于支持这些类型的 ARM 平台，C28x 录波禁止使用。

### C28x 平台适配

- 禁止使用 `uint8`、`int8` 和 `bool` 录波通道，不通过扩宽原生类型来发布类型编码 `0`、`1`、`2`。
- `double` 必须提供 IEEE 754 binary64 的 8 字节表示；若平台原生 `double` 不符合该格式，需要在下位机转换。
- 名称区仍必须是 20 个 8 位 ASCII 字节，通道信息条目仍必须为 38 字节。平台原生 `char` 的宽度不同，不能直接把原生 `char[20]` 内存当作本协议的名称区。
- 帧头、通道信息及允许使用的采样数组必须满足本文的长度和布局；仅使用 `#pragma pack(1)` 不能替代类型宽度和字节表示的适配。

## data：通道采样数组

| 数据项 | 数组定义 | 说明 |
| --- | --- | --- |
| `sample_data1` | `type1[record_length]` | 第 1 个通道的采样数组 |
| `sample_data2` | `type2[record_length]` | 第 2 个通道的采样数组 |
| `…` | `…` | 后续通道按相同方式排列 |

`type1`、`type2` 等表示相应通道类型。布局为：

```text
header
channel_info[0]
channel_info[1]
...
channel_info[channel_num - 1]
sample_data1[record_length]
sample_data2[record_length]
...
sample_dataN[record_length]   // N = channel_num
```

令 `S[i]` 为第 `i` 个通道每个采样值的字节数（由类型编码表确定），通道编号从 `0` 开始：

```text
channel_info_offset(i) = 50 + 38 * i
sample_data_offset(i)  = 50 + 38 * channel_num
                         + record_length * sum(S[j], 0 <= j < i)
total_bytes           = 50 + 38 * channel_num
                         + record_length * sum(S[i], 0 <= i < channel_num)
```

通道采样数组按通道信息条目的顺序连续存放，各通道使用对应类型的字节数。

## 环形缓冲区读取顺序

`current_index` 是下一个采样点的写入位置。每次采样先向该位置写入所有通道的值，再将索引加 1；达到 `record_length` 后回到 `0`。

每个通道始终读取 `record_length` 个点，以 `current_index` 为起点，先读到数组末尾，再读取数组开头至 `current_index` 之前。当 `record_length > 0` 且 `0 <= current_index < record_length` 时，从旧到新的读取方式为：

```text
physical_index(k) = (current_index + k) % record_length
                   // k = 0 .. record_length - 1
latest_index      = (current_index + record_length - 1) % record_length
```

例如，缓冲区已填满，`record_length = 5`、`current_index = 3` 时，按时间从旧到新的物理索引为 `3, 4, 0, 1, 2`，最新值位于索引 `2`。

设备上电后即开始采样，正常使用前缓冲区已经填满。即使在填满前读取，也按上述顺序读取全部槽位；尚未写入的槽位是初始化零值，会排在已有采样值之前一同保存。无需增加有效点数或“已填满”字段。

录波容量由下位机编译时配置，上电即录波，不定义空录波场景。`record_length` 和 `current_index` 由下位机录波逻辑维护。
